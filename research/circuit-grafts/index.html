Circuit grafts

We wired small rule circuits into SmolLM2-135M, a 135-million-parameter language model. On sealed held-out problems, its multiplication score went from 21.3% to 83.1%. No original weight changed, and nothing was trained by gradient descent.

Where this started

One rule can serve many facts

I want to find out how far a small open model can be pushed toward frontier level by editing its weights directly and grafting in new parts, without a heavy training run. Training is the usual route. You push billions of questions and answers through a model and gradient descent works out the rules on its own. But we can also open a model up, read what it holds partway through a problem, and change it. So can some of those rules be written in by hand?

My working theory is that a lot of reasoning runs on rule sets, where one rule serves many facts. Carrying the one is the simplest case. Nobody memorizes every sum, because one carry rule covers all of them, at every digit place. In my notes I put it this way:

Maybe a rule from one fact would coincide with the rule for another.

Facts are expensive for a small model to store, and rules are cheap. The first multiplication circuit in this write-up is built for every problem from 2 × 10 up to 9 × 99, and it's 25,270 weights.

The same conversations turned up a second idea that pairs with the first: a learning ruleset for picking up something new, alongside logic rules for applying what you already know. This write-up is about the logic side.

What the model already has

The digits are in there

Before building anything, we looked at what SmolLM2 holds at the moment it starts writing an answer. A linear read of its hidden state at the answer position, fit by least squares, pulls out the digits of both numbers almost perfectly. For three-digit addition one layer wasn't enough, but joining layers 14, 20 and 21 reads every digit at 99% on fresh problems.

So the model has read the question. What it can't do reliably is combine the digits: the carry, the borrow, the times table. That combining step is the part we supply.

How a graft works

Four parts, none trained by gradient descent

  1. ReadA linear read for each digit of the two numbers, taken from the model's own hidden state.
  2. RulesA small lookup table for each digit of the answer. The units digit comes from the two units digits; the tens digit comes from the tens digits plus the carry, and so on up.
  3. WriteA push toward the right digit token at the model's last layer. The model still writes its own reply. The graft only tips which digit comes next.
  4. SwitchesTwo fitted switches decide when the graft is on. They are fit to fire only while the model writes the answer to this kind of problem, and to stay off on other math, word problems, code and ordinary text.

The reads and switches are fit by closed-form least squares, and the rule tables are written out by a program (by hand, for the first multiplication graft). The base model file is never touched. Each graft is added alongside it.

How it grew

From one graft to a pipeline

  1. Neuron graftThe first try added 24 new neurons to the last layer to supply the carry for two-digit addition. It held up on sealed problems, +19.7 points. It worked by nudging the model's own arithmetic, so the next step was to do the arithmetic outright.
  2. Hand-wired circuitFor multiplication we wrote the rule tables by hand and fed them the model's own digit reads. The first version scored 83.5% on sealed held-out problems, up from 21.3%. A second version with better switches scored 83.1%, and its worst change on other math was −0.75 points.
  3. Rules found by a programA rule-finding program got 340 solved problems as digits and answers. For each answer digit, it looked for the smallest set of inputs that decides it. It found the carry for addition, the borrow for subtraction and the carry chain for multiplication on its own. It also found that the tens digit is the units rule reused on the tens digits, plus a carry step: one rule serving several digits, which is the idea this started from. Its multiplication circuit scored 82.7% held-out, within half a point of the hand-wired one.
  4. Same pipeline, new skillsSubtraction and two-digit addition went through the same script, with settings copied from multiplication and no tuning. Three-digit addition took three fixes, each tested before its held-out set was opened: the read joined from three layers, a second switch, and a push strength set for each digit place.

Results

Five skills, on problems nobody tuned on

Each skill's held-out problems were set aside before any building, and nothing was tuned on them. Every score is two seeds and four runs per problem, with the same sampling settings for the model alone and with the graft. The multiplication set was opened once for the first hand-wired version, then once more for the final two.

  • The scrambled control is the same graft with its wiring shuffled. It scored at or below the model alone on every skill, 2.4% to 21.4%, so the extra weights do nothing without the right rules.
  • The three two-digit grafts (multiplication, subtraction and addition) also run together in one model, 92,496 weights in all. Each kept its gain on dev problems. The worst change on other math was −0.25 points, and 200 of 200 unrelated prompts gave the same answer as before.

Gains are paired by problem, with a one-sided 95% bootstrap lower bound. The side-effect check covers eight other arithmetic and word-problem sets, plus GSM8K and code. Unrelated prompts are 200 IFEval prompts, answered greedily. The rules and predictions for every run were written down before its result.

Against gradient training

Three head-to-heads

Gradient training is the standard way to add a skill, so we ran it as the competitor. Each gradient graft was tuned over a grid of settings before its test.

The circuit's subtraction rules came from 340 problems. The gradient grafts trained on 1,500, the same 1,500 the circuit's digit reads were fit on.

Still in progress

Transplants from bigger models

We're also trying to move skills over from larger models. Qwen3.5-4B got 300 of 300 of these multiplication problems right in our check, so we tried translating a set of its neurons into SmolLM2. Separately, we mapped a correction signal from Qwen3.5-4B into Qwen3.5-0.8B on grade-school word problems. Neither has worked yet, and both are still open. So far the bigger model has been most useful as a guide to where the small one breaks.

What a graft is

A calculator fed by the model's own reading

The graft does the arithmetic itself, from numbers the model already holds. SmolLM2 doesn't learn to multiply. It works on the plain form of the question ("What is 347 + 285?"), and the switches keep it off on word problems on purpose. All of this is one model so far.

The method carries over to new skills. Rules are found by a program from 340 examples, compiled into tables, and placed with the same settings for each skill. Next is the learning side: getting SmolLM2 to use a fact it's handed in the prompt.
